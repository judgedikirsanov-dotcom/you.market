# you.market

Репозиторий проекта «честный поиск товаров». Поиск идёт от лица пользователя: страница открывает выдачи поисковиков, закладка, пользовательский скрипт или расширение разбирают их в браузере, а планировщик запросов, фильтрация и ранжирование карточек выполняются локально — без серверов и прокси.

Сайт: <https://judgedikirsanov-dotcom.github.io/you.market>  
Выпуски: <https://github.com/judgedikirsanov-dotcom/you.market/releases>

На странице только строка поиска и карточки товаров; всё служебное — в свёрнутой панели «технические детали». Что изменилось в версии 3.1.0, как работает «Шаттл» и оценка карточек, как ставить расширение и скрипт из выпуска — в `apps/web/README.md`. Журнал изменений по версиям — в `CHANGELOG.md`.

## Структура

| Путь | Что лежит |
| --- | --- |
| `apps/web/` | Страница, планировщик запросов (`planner.js`), «Шаттл» (`shuttle.js`), выбор канала сбора (`channels.js`), библиотеки моста, закладка, пользовательский скрипт и их тесты |
| `apps/ext/` | Расширение-мост для браузеров на Chromium и на Firefox |
| `apps/helper/` | Локальный помощник — каталог зарезервирован, кода пока нет |
| `apps/api-proxy/` | Прокси с ключами — каталог зарезервирован, кода пока нет |
| `tools/` | Сборщик закладки (`build_bookmarklet.js`), единая версия и её сверка (`versions.js`, `check_versions.js`), сборка выпуска (`make_release_dist.js`, `release_notes.js`) и тесты |
| `version.json` | Единственный номер версии продукта и номер формата данных |
| `CHANGELOG.md` | Журнал изменений; раздел текущей версии уходит в заметки о выпуске |
| `.github/workflows/` | Сценарии `checks` (проверки), `publish-web` (публикация сайта) и `release` (выпуск по метке) |

## Проверки и сборка

Нужен Node.js 24. Из корня репозитория:

```
node apps/web/tests/web_tests.js
node apps/web/tests/planner_tests.js
node apps/web/tests/shuttle_tests.js
node tools/test_bridge_lib.js
node tools/test_release_dist.js
node tools/build_bookmarklet.js --check
node tools/check_versions.js
```

Это те же проверки, что идут в сценарии `checks` на каждую отправку и в каждом запросе на слияние: тесты ядра, планировщика, «Шаттла», библиотеки моста и сборщика выпуска; сборка закладки «пересобрать и сравнить» (ловит страницу или закладку, поправленные руками); сверка версий. Сценарий `checks` дополнительно собирает папку выпуска и сверяет её повторной сборкой.

Сборка — `node tools/build_bookmarklet.js`: пересобирает `apps/web/bookmarklet.js`, вписывает готовую закладку в `apps/web/index.html` и проставляет номер из `version.json` во все части продукта. Её нужно запускать после изменения `bridge-lib.js`, `tools/bm_action.js` и после смены версии, а результат — коммитить.

## Единая версия

Номер хранится один раз — в `version.json` — и проставляется сборщиком в пять мест: `?v=` у библиотек страницы, метка `you-market-version` в `index.html`, `@version` и `@require` пользовательского скрипта, поле `version` обоих манифестов расширения. `node tools/check_versions.js` падает, если где-то остался чужой номер; с ключом `--tag vX.Y.Z` сверяет метку релиза с `version.json`.

## Выпуск версии

Выпуск собирается по метке: метка `vX.Y.Z` на вершине `main` запускает сценарий `release`, который проходит те же проверки, собирает папку `dist/` (архив расширения, скрипт, `SHA256SUMS.txt`, `latest.json`), подписывает её аттестатом сборки и создаёт релиз с заметками из `CHANGELOG.md`. Постоянные ссылки вида `releases/latest/download/<имя-файла>` отдают файлы последнего выпуска. Пошаговый порядок — в `apps/web/README.md`, раздел «Как выпустить версию».

## Отправка изменений

```
bash push.sh "что изменилось"
```

Первая отправка и все следующие — одна и та же команда: скрипт сам делает коммит и отправляет его в GitHub. Сам `push.sh` в коммит не попадает. Сайт публикуется из этого же репозитория через GitHub Pages (`.github/workflows/publish-web.yml`): после отправки в main сценарии `checks` и `publish-web` повторяют тесты, сверку сборки и версий и публикуют папку сайта; вручную — вкладка Actions → publish-web → Run workflow. Чтобы публикация заработала, один раз включите Pages: Settings → Pages → Source: «GitHub Actions».
