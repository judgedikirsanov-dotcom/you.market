# честный поиск товаров — клиентская версия (filter-search-web) v9-v12

Одностраничник без серверов и прокси: **всё выполняется в браузере
пользователя и от его лица** — его вкладки, его IP, его куки. Поисковик видит
обычного человека, а не бота: мы не конкуренты поисковым системам, мы их
активные пользователи, просто немного более продвинутые.

**Демо:** https://judgedikirsanov-dotcom.github.io/you.market
(бесплатный статический Space Hugging Face; исходник — папка `filter-search-web`).

## Как работает поиск (v6)

Пользователь вводит запрос и жмёт «искать». Дальше:

1. **страница открывает popup-окна поисковиков каскадом «друг под другом»** —
   Google, Яндекс (исходный русский запрос), Bing и DuckDuckGo-lite (переведённый,
   как в англоязычном магазине; lite не рвёт opener и не закрывает своё окно —
   вкладка отчитывается и закрывается сама); Brave/Mojeek/Marginalia и
   Ozon/Avito/AliExpress — тоже сразу
   (оттуда цены в рублях); Brave/Mojeek/Marginalia — кнопками в чипах.
   v15: карточки площадок (Ozon/Ali/Avito/магазины) больше не прячутся строгим
   фильтром слов: площадка сама искала по запросу — пропуск слова в названии
   лишь помечает «частичное совпадение» (раньше при запросе «велосипед sava
   al pro» в карточках оставались одни ролики youtube, а ценовые карточки
   Ozon/Ali скрывались). Многопрогонный фильтр: строгий → мягкий, берётся
   первый прогон с ценой; при равной релевантности карточка с ценой выше.
   v14: открываются сразу ВСЕ 10 источников (Brave/Mojeek/Marginalia тоже);
   отчёты дедуплицируются (скрипт+расширение одновременно — дубль не пролезет);
   AliExpress ?SearchText=… распознаётся (окно больше не висит); карточки
   отсортированы по совпадению с запросом («sava al pro» → 3/3 сверху, слабые
   — в свёрнутый блок); карточка товара с картинкой из выдачи (ecatalog-стиль).
   v13: каждое окно сайта открывается с маркером &fsx=1 — скрипт-мост v2.3
   авто-отчитывается ТОЛЬКО в таких окнах; обычные поиски пользователя из
   адресной строки он не перехватывает (на чужих вкладках — лишь кнопка
   «📨 в фильтр» и Alt+S по желанию). Без менеджера юзерскриптов —
   расширение-мост filter-search-ext (Chrome: «загрузить распакованное»,
   Firefox: about:debugging → временно): оно знает свои вкладки по tabId
   и не трогает чужие в принципе. **Последним открывается
   окно-анимация (#fsWorker)**: оно перекрывает всю стопку, показывает живой
   прогресс (чипы источников загораются по мере поступления данных) и само
   закрывается на «готово» (это same-origin popup, открытый нашим
   window.open — close() разрешён);
2. в каждой вкладке выдача исследуется **прямо на месте**:
   - **кнопка-закладка (букмарклет)** — один клик по закладке «📨 в фильтр
     товаров»; код полностью инлайновый (CSP поисковиков javascript:-URL
     закладок не запрещает), работает в Firefox, Chrome, Safari, Edge —
     расширений не нужно;
   - **пользовательский скрипт** (`filter-search.user.js` для
     Violentmonkey/Tampermonkey) — то же самое **без единого клика**:
     вкладка отчитывается и закрывается сама через ~1.8 с после загрузки;
   - парсеры вынимают результаты **и ИИ-ответы поисковиков** (Google AI
     Overview, Яндекс Нейро, Bing Copilot, Brave AI) — DOM-эвристики +
     regex-запасной путь;
3. данные попадают на страницу агрегатора по **вкладке-почтальону**:
   - если `window.opener` жив (мелкие поисковики) — `opener.postMessage`;
   - Google/Яндекс/Bing рвут opener заголовками COOP — тогда букмарклет
     навигирует окно на наш сайт с данными в адресе (`#fsRelay=<base64url>`),
     страница-релей на нашем же origin передаёт payload агрегатору через
     **BroadcastChannel** и закрывает окно сама;
   - **закрытие (v9-v12): релей пробует `window.close()` всегда**, а не только при
     `history.length > 1` — после `location.replace` у окна одна запись истории,
     и по правилу спецификации (script-opened ИЛИ одна запись) браузер
     разрешает close; если браузер всё же отказал — окно честно показывает
     «✓ передано — закрой Ctrl+W» вместо тихого зомби;
   - на «готово» главная страница шлёт `fsWorkerDone` окну-анимации и пробует
     закрыть свои popup-окна (`closeOurWindows`); вкладки, открытые вручную,
     кладут выдачу в буфер обмена → кнопка «📥 забрать из буфера»
     (permission `clipboard-read`) или Ctrl+V;
4. две выдачи → итог собирается сам: карточки с источниками, перекрёстные
   подтверждения, медиана рынка; поздние вкладки вольются и пересчитают;
5. фильтр скрывает подделки, «Case for X», чужие модели, подозрительные цены —
   и объясняет каждое скрытие. ИИ-ответы показываются отдельной сводкой
   сверху (фиолетовая карточка) — это справка поисковика, в медиану не входит.

## Файлы

| файл | что это |
|---|---|
| `index.html` | страница: setup закладки (перетащи в панель), поле запроса, курьер, чипы, стадии ①-⑥, карточки + ИИ-сводки, «собрать итог», экспорт. Никаких iframe |
| `filter-core.js` | ядро фильтра v4: подделки, аксессуары, соответствие запросу, медиана по валютам |
| `core.js` | парсеры (Google/Яндекс/Bing/DDG/Mojeek/Ozon/Ali/Avito, JSON-LD/OG), сравнение выдач, detectBlock (в т.ч. капча DDG), Shopify-канал, URL поисковиков |
| `bridge-lib.js` | **единая библиотека моста**: парсеры выдач + ИИ-экстракция + collect/buildPayload/validatePayload. Один исходник для сайта, скрипта (@require) и букмарклета (инлайн через build_bookmarklet.js) |
| `app.js` | конвейер v9-v12: каскад popup-окон + окно-анимация #fsWorker, приём postMessage + BroadcastChannel + #fsRelay, безусловное самозакрытие релея, ИИ-карточки, дедуп по ts, честные чипы |
| `filter-search.user.js` | тонкий скрипт-мост v2.1: авто-отчёт вкладки (opener → postMessage, иначе релей) + Alt+S/кнопка |
| `bookmarklet.js` | собранный инлайн-код букмарклета (исходник для правок; в index.html попадает через сборку) |
| `tests/web_tests.js` | 93 офлайн-проверки ядра |

Сборка букмарклета: `node tools/build_bookmarklet.js` (выполняется
автоматически перед деплоем; кладёт инлайн в `<a id="bmLink">`).

  popup-стопка открылась каскадом, окно-анимация — последним и в фокусе;
  чипы worker загораются от BroadcastChannel-потока; на `fsWorkerDone`

  сам закрывает свои popup-окна (их анти-автоматизация, не наш баг);

  реальной вкладке Bing передал 10 результатов через вкладку-почтальон;
  DDG-антибот честно распознался как капча; при 2 источниках итог собрался сам.

## Почему без прокси и серверов

Публичные CORS-прокси (v5) работают с IP дата-центров — поисковики отдают им
капчи и мусор, то есть «спамботную» выдачу. Наш инструмент должен видеть
ровно то, что видит человек, поэтому источник выдачи — только вкладка
пользователя. Хостинг тоже не нужен: Hugging Face бесплатно держит статику
(gradio/docker-Spaces требуют PRO — проверено API 2026-11-24). Всё, что
страница не может сделать сама (прочитать чужую вкладку), делает букмарклет
или скрипт руками пользователя — это физический предел браузера, и он же
является границей приватности: выдача передаётся через собственные вкладки и
буфер пользователя, серверов в цепочке нет.

## Границы (честно)

- Google/Яндекс из дата-центра (IP песочницы/прокси) капчатся — у пользователя
  с домашним IP и своими куками будет настоящая выдача; если поисковик всё же
  показывает капчу — чип честно это покажет: решите её во вкладке и нажмите
  закладку снова;
- вкладка-почтальон закрывается сама, если была открыта сайтом; вкладки,
  открытые вручную, браузер не даёт закрыть скриптом — на странице-релее
  появится подсказка «вкладку можно закрыть»;
- вёрстка поисковиков меняется: парсеры в `bridge-lib.js` (букмарклет/скрипт)
  и `core.js` (агрегатор) синхронны по логике; при неполадках payload несёт
  весь HTML — агрегатор разберёт сам.

## Обновление из чата

Правки вносятся в `apps/web/`, гоняются
тесты, затем:

```bash
bash scripts/deploy_hf_static.sh   # сборка букмарклета → тесты → push → URL
```

Токен — `scripts/.hf_token` (chmod 600). Каталог деплоится на любой хостинг
статики без правок кода.
